# 구현 계획

## 파일 구성
| 파일 | 내용 |
|---|---|
| `streamlit_app.py` | 화면(로그인, 학생 화면, 관리자 화면) |
| `tf/rules.py` | 규칙 검사(주 역할 중복, 필수 포함 역할 자리), 배정안 검사 5가지, 모든 경우를 따지는 배정 탐색 |
| `tf/ai.py` | 오픈라우터 호출, 1~3차 모델 폴백, 모델마다 120초 전체 대기 제한 |
| `tf/db.py` | Supabase 연결(연결 풀 재사용, 끊긴 연결 복구), 질의 함수 |
| `tf/service.py` | 지원, 투표, 마감, 명단 올리기, 확정 같은 동작 |
| `schema.sql` | `tf_` 테이블과 제약 |
| `tests/` | 규칙과 연습용 시나리오 3개를 확인하는 테스트 |

## 단계
1. `schema.sql`로 Supabase에 테이블을 만든다.
2. `tf/rules.py`의 규칙 함수와 배정 탐색을 만들고 단위 테스트로 확인한다.
3. `tf/db.py`, `tf/service.py`로 지원, 투표, 마감, 확정을 만들고, 연습용 시나리오 3개를 코드로 돌려 기대 결과와 비교한다.
4. `tf/ai.py`로 AI 배정을 만든다. 실패하면 다음 모델로, 3차까지 실패하면 탐색 결과를 쓴다.
5. `streamlit_app.py`에 화면을 만들고 공고 2.7절의 `key`를 붙인다.
6. 브라우저로 연습용 시나리오 3개를 직접 해 보고, 화면을 `img/`에 남긴다.
7. 깃허브 비공개 저장소에 올리고 Streamlit Community Cloud에 배포한다. Secrets를 넣고 앱을 공개로 바꾼다.
8. GitHub Actions로 매일 DB에 질의해 일시정지를 막는다.
9. `README.md`를 공고 7.1절 양식으로 쓰고, 커밋한 파일만 zip으로 만든다.
