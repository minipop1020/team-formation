# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트를 위한 팀을 스스로 편성한다. 지원과 팀원 투표로 팀을 만들고, 모집 마감 뒤 팀이 없는 학생은 AI가 배정안을 내며, 앱이 그 배정안을 규칙으로 검사한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생 | 학번과 비밀번호(1234)로 로그인. 팀 목록과 팀원의 주/보조 역할을 봄. 팀에 지원. 내 팀에 들어온 지원에 찬성/거부 |
| 관리자 | 학번 `admin`, 비밀번호는 비밀 값 `ADMIN_PASSWORD`. 명단 CSV와 팀 수로 처음 상태를 만듦. 모집 마감. AI 배정안을 받아 확인하고 확정 |

## 3. 역할
- 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자
- 학생마다 주 역할 1개, 보조 역할 0~2개(명단 CSV로 정해짐)

## 4. 팀 규칙
1. 관리자가 정한 수만큼 팀을 만든다(팀1, 팀2, …).
2. 확정한 팀은 모두 2~4명(빈 팀 없음).
3. 한 팀에 주 역할이 같은 학생이 2명 이상이면 안 된다.
4. 모든 팀에 기획자와 웹 프로그래머를 맡을 학생이 서로 다른 사람으로 1명씩 있어야 한다(주 역할이나 보조 역할).

## 5. 지원과 투표
- 빈 팀에 지원: 바로 승인
- 팀원이 있는 팀에 지원: 대기. 투표하는 때의 팀원 모두가 찬성하면 승인, 한 명이라도 거부하면 바로 거절
- 승인 직전에 규칙(정원, 주 역할 중복, 필수 포함 역할 자리)을 다시 검사해 어기면 거절
- 막힘(지원을 접수하지 않음): 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 이미 팀이 있거나 결과를 기다리는 지원이 있음, 모집 마감, 필수 포함 역할을 맡을 학생의 자리가 모자람
- 투표는 바꿀 수 없음

## 6. 마감과 배정
1. 마감하면 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐
2. 규칙을 지키는 배정이 아예 없으면 AI를 부르지 않고 이유를 보여 줌
3. AI 배정: 오픈라우터 무료 모델 1차 → 2차 → 3차. 모델마다 전체 대기 120초
4. 배정안 검사 5가지: 빠짐없이 배정, 한 학생은 한 팀, 모든 팀 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족
5. 3차까지 실패하면 앱이 모든 경우를 따져 규칙을 지키는 배정을 찾음
6. 검사를 통과한 배정안만 관리자에게 보여 주고, 확정하면 DB에 저장

## 7. 기능별 해결 방법(모두 어려운 해결)
| 기능 | 해결 |
|---|---|
| 다른 사람의 변경 보기 | `st.fragment`로 3초마다 다시 그림 |
| 필수 포함 역할을 지킬 수 없는 팀 | 지원 단계에서 자리가 모자라게 되는 지원을 막음 |
| 같은 팀에 대기 중인 지원이 여럿 | 승인 직전에 규칙을 다시 검사 |
| 마지막 자리에 두 명이 동시에 들어감 | DB 유일성 제약 (`tf_members`) |
| AI 응답이 늦을 때 | 모델마다 120초 전체 대기 시간을 재서 끊음 |
| 3차 모델까지 실패 | 모든 경우를 따지는 탐색으로 배정 |
| AI 대기 중 화면 | 몇 차 모델을 기다리는지와 경과 시간 표시 |
| DB 일시정지 막기 | 외부 예약 서비스(GitHub Actions)로 매일 DB 질의 |

## 8. 기술
- Python, Streamlit(Community Cloud 배포), Supabase Postgres(`psycopg`), `bcrypt` 비밀번호 해시, OpenRouter API
- 키(`OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`)는 `.env`와 Streamlit Secrets에만 둔다.
- 화면 요소의 Streamlit `key`는 공고 2.7절 표를 그대로 따른다.
